    \noindent\textbf{Abstract.}
    Cloud authorization logs record \emph{who} accessed a resource but often
    omit \emph{why} the access occurred. This gap allows a stolen short-lived
    credential to blend into ordinary service-to-service traffic. We present
    \system, a detection layer that propagates a compact, authenticated causal
    context across remote procedure calls and checks each privileged action
    against a learned service workflow. The design joins request provenance
    with existing identity signals without placing policy decisions on the
    critical path. In a 48-service testbed replaying 12 production-derived
    workflows, \system{} detects 94.7\% of cross-service credential-abuse paths
    at 0.31 alerts per 10,000 requests, including attacks that preserve the
    victim service's identity and network location. Median request overhead is
    38~$\mu$s and context adds 72 bytes per hop. These preliminary results
    suggest that causal context can close an important observability gap while
    remaining compatible with incremental deployment.

    \vspace{4pt}
    \noindent\textbf{Keywords:} cloud security, credential abuse, distributed
    tracing, provenance, anomaly detection

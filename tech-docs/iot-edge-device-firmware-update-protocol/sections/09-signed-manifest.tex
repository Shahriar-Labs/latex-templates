\section{Signed manifest}

\subsection{Canonical form and signature}

The signed payload is a canonical CBOR map. It is wrapped in a COSE\_Sign1
structure whose protected headers contain the algorithm and \field{kid}. The
signature covers the exact canonical payload bytes. Gateways and repositories
\mustnot rewrite, normalize, or reserialize a signed payload.

The device validates the manifest in this order:

\begin{enumerate}
  \item parse with strict size, type, duplicate-key, and canonical-encoding checks;
  \item select a trusted key by protected \field{kid} and authorized signer role;
  \item verify the COSE signature over the original payload bytes;
  \item verify protocol and manifest schema versions;
  \item enforce validity, revocation, target, dependency, and anti-rollback rules;
  \item select exactly one compatible artifact for each required component; and
  \item persist the manifest digest before beginning transfer.
\end{enumerate}

No artifact URL, filename, content type, or server response header is security
authoritative unless its value is bound into the signed manifest.

\subsection{Artifact descriptor}

Each component contains one or more artifact alternatives. An artifact descriptor
\must contain \field{artifact_id}, \field{format}, \field{size}, \field{sha256},
\field{compression}, \field{chunk_size}, \field{chunk_hashes}, and at least one
HTTPS \field{uri}. It also contains the resulting installed-image digest and
security version when downloaded bytes are compressed, packaged, or a delta.

\subsection{Applicability rules}

An offered manifest is applicable only when all of the following are true:

\begin{enumerate}
  \item the signature and signer role are valid;
  \item the protocol version lies within \field{protocol_min} and
        \field{protocol_max};
  \item product, model, and hardware revision match the signed target expression;
  \item all critical fields and required components are understood;
  \item dependencies are satisfied before the dependent component is activated;
  \item each selected artifact matches a reported capability;
  \item its release sequence and image security version satisfy Section~\ref{sec:rollback};
  \item the release and artifact are not present in signed revocation metadata; and
  \item installation constraints can be satisfied without risking the confirmed image.
\end{enumerate}

Target expressions are positive allow-lists. Empty target lists match nothing.
Wildcards, regular expressions, and negative matches are forbidden in version 1
to keep evaluation deterministic. Group targeting is an operational filter and
\must be backed by authenticated provisioning state if used as a signed target.

\subsection{Pipeline controls}

Pull requests require code ownership, passing tests, policy checks, secret scanning, dependency scanning, and an approved plan for infrastructure changes. Production promotion requires environment approval and is blocked during an active major incident. The pipeline assumes a narrow AWS role through OIDC, records artifact provenance, and writes deployment events to the audit trail.

Deployments use canary steps of 5\%, 25\%, 50\%, and 100\%, advancing only while SLO and application checks remain healthy. Automated rollback returns traffic to the prior signed image. Database migrations are forward-compatible and are not treated as reversible container deployments.

\subsection{Infrastructure repositories and state}

Terraform modules define organization, account, network, cluster, data, security, and observability layers. State is encrypted in a dedicated administrative account with locking, versioning, and access logging. Each environment has independent state and roles. Drift detection runs daily; critical drift alerts the platform team and cannot be silently adopted.

\section{Data Model \& Schemas}

\subsection{Metadata Catalog Schema}
Metadata operations are critical for maintaining strong tenant isolation and tracking object versions. Table~\ref{tab:metadata_schema} defines the layout of the primary database table used by AGS-Meta to store object location mappings.

\begin{table}[h]
    \centering
    \sffamily
    \small
    \begin{tabularx}{\linewidth}{l l l L}
        \toprule
        \textbf{Field Name} & \textbf{SQL Type} & \textbf{Key Type} & \textbf{Description} \\
        \midrule
        \texttt{tenant\_id} & \texttt{UUID} & Primary (Composite) & Identifies the customer account owner. \\
        \texttt{bucket\_name} & \texttt{VARCHAR(63)} & Primary (Composite) & Unique container namespace inside the tenant. \\
        \texttt{object\_key} & \texttt{VARCHAR(1024)} & Primary (Composite) & Unique identifier path for the stored object. \\

\subsection{API Payload Specifications}
Write requests to the object store are initiated via a gRPC transaction. The protobuf definition in Listing~\ref{lst:grpc_api} illustrates the request and response structure for the object creation sequence.

\begin{lstlisting}[language=c, caption={Protobuf definition for the write path API.}, label={lst:grpc_api}]
syntax = "proto3";
package apex.storage.v2;

service ObjectStorageService {
  rpc InitializeUpload(UploadRequest) returns (UploadResponse);
}

message UploadRequest {
  string tenant_id = 1;
  string bucket_name = 2;
  string object_key = 3;
  int64 expected_size = 4;
}

message UploadResponse {
  string upload_token = 1;
  repeated BlockTarget block_targets = 2;
  int64 expires_at = 3;
}

message BlockTarget {
  string block_id = 1;
  string node_address = 2;
}
\end{lstlisting}

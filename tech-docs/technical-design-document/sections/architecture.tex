\section{System Architecture}

\subsection{Architectural Paradigm}
Apex Global Storage (AGS) utilizes a decoupled architecture where control plane operations (metadata management) are separated from the data plane operations (block transfer). This separation allows metadata nodes to be optimized for low-latency transaction processing, while data storage nodes are optimized for high-bandwidth disk operations.

\subsection{Component Breakdown}
The system is divided into four main subsystems, which are deployed independently:
\begin{itemize}
    \item \textbf{Ingress Gateway (AGS-Gateway):} Decrypts incoming TLS traffic, authenticates tenant credentials, rates limits requests using a token bucket algorithm, and routes requests.
    \item \textbf{Metadata Engine (AGS-Meta):} Handles namespace resolution, access control checks, directory structures, and file-to-block allocation mapping. It utilizes a distributed CockroachDB backend for transactions \cite{rostova2023metadata}.
    \item \textbf{Storage Engine (AGS-Store):} Manages raw storage pools on storage nodes. It writes payload streams directly to NVMe-backed block files, bypassing traditional file-system caches to eliminate latency jitter.
    \item \textbf{Replication Coordinator (AGS-Replica):} Orchestrates async replica synchronization and parity check background tasks.
\end{itemize}

\begin{warnbox}[Operational Constraint]
    The AGS-Gateway nodes must have at least 10Gbps network links. Any reduction in interface bandwidth directly leads to client queue backpressure, causing request drops at the load balancer.
\end{warnbox}

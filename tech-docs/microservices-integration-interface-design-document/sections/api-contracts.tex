\section{Synchronous API Contracts}

\subsection{Gateway and Versioning}
All synchronous traffic between services is routed through the Nexa API gateway and is
versioned in the URI path, currently \code{/v2}. A new major version is introduced only for
breaking changes; additive changes (new optional fields, new endpoints) ship within the
current version. See Section~6 for the full versioning policy.

\subsection{Authentication and Transport Security}
Every gateway-routed call requires two layers of trust:
\begin{itemize}[leftmargin=1.6em]
  \item \textbf{Mutual TLS} between the gateway and each downstream service, terminated at the
    service mesh sidecar, with certificates rotated every 90 days.
  \item \textbf{A short-lived JWT bearer token} (5-minute expiry) issued by the internal
    service-identity provider and validated by the gateway before the request is forwarded.
\end{itemize}
Partner-owned services (Synapse, Vertex, Nimbus) authenticate the same way; there is no
separate ``partner'' auth path, which keeps the trust model uniform across ownership
boundaries.

\subsection{Pagination and Rate Limiting}
List endpoints use cursor-based pagination via a \code{cursor} query parameter and return a
\code{nextCursor} field; page size is fixed at 50 and is not client-configurable. Every
authenticated client is limited to 300 requests per minute per service, enforced at the
gateway; the response headers \code{X-RateLimit-Remaining} and \code{X-RateLimit-Reset} report
the current window. Exceeding the limit returns \code{429} with the error envelope described
in Section~5.

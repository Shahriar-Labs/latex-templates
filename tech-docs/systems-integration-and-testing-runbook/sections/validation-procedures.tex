\subsection{Validation Query: Ledger Write Consistency}
INT-043 is checked directly against the ledger cluster rather than through the API, so that a
bug in the adapter's own reporting cannot mask a duplicate write. Run this after the smoke
suite in Step 3 and again after promotion in Step 4.

\begin{cmdbox}[Ledger Postgres]
\promptline{psql -h ledger-prod-aps1.vertex.internal -U ro\_validator -d ledger -c \textbackslash}
\hspace*{1.4em}"SELECT intent\_id, COUNT(*)\\
\hspace*{1.4em}FROM settlement\_records\\
\hspace*{1.4em}WHERE created\_at > now() - interval '1 hour'\\
\hspace*{1.4em}GROUP BY intent\_id HAVING COUNT(*) > 1;"
\end{cmdbox}

The query must return zero rows. A nonzero result means the adapter is double-writing on
retry and is a hard rollback trigger regardless of what the latency dashboard shows.

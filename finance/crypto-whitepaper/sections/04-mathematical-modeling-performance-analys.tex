\section{Mathematical Modeling \& Performance Analysis}
To validate the throughput capabilities of the VertexDAG consensus, we define a theoretical model for transaction processing capacity. Let $T(N)$ define the throughput as a function of the active validator set size $N$:
\begin{equation}
T(N) = \frac{\lambda \cdot B}{1 + \gamma \log(N)}
\end{equation}
where $\lambda$ represents the validator block-proposal frequency, $B$ is the average batch size per block, and $\gamma$ is the network latency coefficient. The logarithmic penalty term $\log(N)$ models the propagation delay across the peer-to-peer network overlay.

The average finality latency $\mathcal{L}$ is defined by:
\begin{equation}
\mathcal{L} = D_{net} + \tau_{verify} + \epsilon_{proof}
\end{equation}
where $D_{net}$ is the network diameter propagation delay, $\tau_{verify}$ is the topological ordering verification time, and $\epsilon_{proof}$ is the zero-knowledge proof generation and validation overhead.

Under high network congestion, the transaction fee pricing model dynamically adjusts to prevent network saturation. The fee equation for transaction $tx$ is formulated as:
\begin{equation}
f_{tx} = f_{base} \cdot (1 + \omega \cdot U_{net}) + \text{Tip}_{user}
\end{equation}
where $f_{base}$ is the static protocol fee, $U_{net} \in [0, 1]$ represents the fraction of network bandwidth utilized, and $\omega$ is the fee sensitivity exponent.

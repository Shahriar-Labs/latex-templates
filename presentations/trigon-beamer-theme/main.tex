\section{Introduction \& Challenges}

% Slide 4: Bullet Builds
\begin{frame}{Introduction to Edge-Cloud Dynamics}
  Managing workloads across decentralized networks requires addressing core constraints:
  \begin{itemize}[<+-| alert@+>]
    \item \faServer\ \textbf{System Heterogeneity:} Node capacity varies by orders of magnitude.
    \item \faNetworkWired\ \textbf{Workload Volatility:} Network demand fluctuates unpredictably.
    \item \faClock\ \textbf{Telemetry Latency:} Centralized scheduling suffers from sync delay.
  \end{itemize}
\end{frame}

% Slide 5: Columns Slide
\begin{frame}{The Centralization Bottleneck}
  \begin{columns}[T]
    \begin{column}{0.48\textwidth}
      \textbf{Traditional Orchestration Limits:}
      \vskip 0.8em
      \begin{itemize}
        \item High latency overhead due to backhaul round-trip times.
        \item Single points of failure during network partition events.
        \item Inefficient local resource utilisation under burst traffic.
      \end{itemize}
    \end{column}
    \begin{column}{0.48\textwidth}
      \begin{tcolorbox}[colframe=tPrim, colback=tBg, title=Proposed Objectives]
        We introduce the \textbf{Vertex} framework: a decentralized scheduling model designed to balance workloads locally, using predictive local states before querying Nimbus cloud databases.
      \end{tcolorbox}
    \end{column}
  \end{columns}
\end{frame}

% Slide 13: Summary
\begin{frame}{Key Research Findings}
  \begin{itemize}
    \item \textbf{Decentralized Efficiency:} P2P sync reduces orchestration overhead by up to 54\% compared to central cloud architectures.
    \item \textbf{Robust Scaling:} Execution overhead remains bounded as network nodes scale.
    \item \textbf{Fault Tolerance:} The model sustains high packet loss ratios without service degradation.
  \end{itemize}
